# Review

A read of this repository against its own claims, done on 2026-10-23 on Windows 11 with
CPython 3.13.5 in a fresh virtual environment. CI runs 3.11; where that matters it is
said. Every number below came from a run recorded here.

## What it is

The record of a five-step seminar that takes one calibrated HBV001a rainfall-runoff model
and asks how much of its apparent skill survives the uncertainty around it: in the
parameters, in the rainfall that drives it, and in the discharge it is scored against.

The finding is the part worth keeping: **the observations are the weak point.** Realistic
noise on the rainfall leaves the fit essentially untouched, at NSE 0.9073 against 0.9076.
Propagating realistic rating-curve error into the observed discharge costs about 0.15 of
NSE, to 0.7592, and recalibrating against the corrupted record wins back almost none of
it.

Everything CI runs, locally.

| Lint | `ruff check scripts/` | **All checks passed** |
| Artifacts and figures | `python scripts/check_repository.py` | **Passed.** 11 required artifacts, and 16 result files behind 4 figures are the committed ones. 13 after this change adds both diagrams |

**Two of those deserve emphasis.**

`check_claims.py` re-derives **37 headline claims** from the result files and fails if the
README disagrees with any of them. No other repository in this portfolio checks its prose
that thoroughly, and all 37 passed.

The four figures regenerated **byte-identically** on matplotlib 3.11.2 and numpy 2.5.4,
which are almost certainly newer than the versions they were committed with. That is a
stronger reproducibility result than the repository claims for itself.

## What was wrong

### 1. The workflow diagram was generated, CI-verified, and invisible

`docs/diagrams/workflow.svg` is produced from the result files, and the CI step
*"Workflow diagram regenerates identically"* fails if a byte moves. It is a good diagram
and it was referenced **nowhere in the README** except as a filename in the reproduce
instructions. CI was protecting a picture no reader ever saw.

The README now opens the sequence with it, through a `<picture>` element, directly under
the paragraph that states the finding.

### 2. The diagram was light-only, and shipped a contrast failure

There was one SVG. It paints its own opaque `#FFFFFF` background with `#111827` ink and
has no `prefers-color-scheme`, no `currentColor` and no dark variant, so on a dark GitHub
page it stayed legible and read as a sheet of paper dropped onto the page. Every other
repository in this portfolio serves a `-dark` variant through `<picture>`; the
`mcp-policy-gateway` generator says in its own comment that its dark palette exists "so
the diagram does not show up as a white rectangle on a dark background". This was that
rectangle.

Adding the second theme meant measuring the first, and **the committed light diagram was
already failing WCAG AA on its captions**:

| Class | Colour | On the paper | Floor |
|---|---|---|---|
| `.cap` captions, light, **before** | `#9CA3AF` | **2.54:1** | 4.5:1 |
| `.cap` captions, light, after | `#6B7280` | **4.83:1** | 4.5:1 |
| `.cap` captions, dark, first attempt | `#6E7681` | **4.12:1** | 4.5:1 |
| `.cap` captions, dark, after | `#7D8590` | **5.07:1** | 4.5:1 |

Every text class was measured against every fill it is actually drawn on, three classes
over five fills. The minimum that a reader can land on is now **4.83:1 in light and
5.07:1 in dark**. The caption colour is also the arrow colour, so the arrows were faint
for the same reason and are no longer.

`faint` on a coloured panel measures below the floor in both themes and is excluded from
that minimum deliberately, because the diagram never draws a caption on a panel: both
`.cap` strings sit at y=632 and y=652, below every box.

**Two mistakes of mine inside this change, both caught by checking.** The first dark SVG
came out with light ink on a hard-coded `#FFFFFF` background, because the background rect
did not read from the palette; it was unreadable. And the obvious dark caption colour,
`#6E7681`, measured 4.12:1 and would have shipped the same class of failure into the new
theme.

### 3. `ruff` was installed unpinned in CI

`python -m pip install ruff` with no constraint. A lint result then depends on the day the
job ran: an upstream release that adds a rule turns the build red with no change to the
code. `insureassist-rag-mlops` has a comment in its own requirements recording that this
happened there twice in one day. Pinned to `ruff==0.17.2`, the version this review ran.

### 4. No `permissions` block and no `timeout-minutes`

The job only reads the repository and publishes nothing, so `contents: read` is the whole
requirement. Runs finish in about 40 seconds, and the cap is 15 minutes.

### 5. Two actions on deprecated Node

`actions/checkout@v4` and `actions/setup-python@v5` target Node 20. Moved to `@v7`, the
versions verified green elsewhere in this portfolio.

### 6. The CI diagram check named only one file

`git diff --exit-code -- docs/diagrams/workflow.svg`. With a dark variant that would have
left the second file free to drift from the numbers in `results/`. It now names both.

### 7. `check_repository.py` could not see a deleted diagram

Its `REQUIRED` tuple listed neither SVG. The regeneration step catches a *changed* file
but not a *deleted* one: the generator would recreate it as untracked and `git diff` would
report nothing. Both are in `REQUIRED` now, so the count goes from 11 to 13.

### 8. A stale local branch

`backup-2026-10-15/main` had **zero** commits not already on `main`: 0 ahead, 15 behind,
and a clean ancestor. It was on no remote. Deleted locally.

### How the light diagram stayed trustworthy through a palette refactor

The light palette's values are unchanged except the caption colour, and the drawing code
is untouched. The refactor mutates module-level colour names in `apply_theme` rather than
threading a palette through about twenty `box()` and `arrow()` calls, which is the
unlovely choice taken on purpose: it keeps the light path the same code it always was, so
the only difference in its output is the one colour that was deliberately changed.

`arrow`'s default colour moved out of the signature, because a default binds once at
import and would have pinned every arrow to whichever theme ran first.

Both files were generated twice and compared by hash: identical. CI re-checks that on
every run.

### The Mermaid diagram

Not a redrawing of the SVG, and placed under it rather than instead of it. The SVG is the
precise version, generated from the result files. The Mermaid one is the version that
renders when an image does not, and it makes the shape of the finding visible: two
branches off the calibrated model, one for error in the input and one for error in the
output, with the measured NSE at the end of each. Its five numbers are the generator's own
output, not the prose.

## The secret scan

`gitleaks git .` over the full history, 50.69 MB scanned: **no leaks found**, with no
false positives to triage either. That is the cleanest result of any repository in this
pass, and unsurprising given what is in here: the result files are numeric output and the
archives are LaTeX sources.

## The website agrees with this repository

`ZQ/src/content/hydrology-world.ts` pins commit `7a5cf09`, which is **16 commits behind
`main`** but a clean ancestor. That distance does not matter here, and it was checked
rather than assumed: **all four cited result files are byte-identical between the pin and
`main`**, so every published number is true at both.

Verified against the pinned files, value by value:

| Site states | Pinned file |
|---|---|
| `nse: 0.9076` | `final_nse: 0.9076082110404968` |
| `ofv: 0.092392` | `1 - 0.9076082110404968 = 0.0923918` |
| `referenceNse: 0.907715` | `1 - 0.092285` |
| `referenceOfv: 0.092285` | `Reference OFV: 0.092285` |
| `evaluations: 75480` | `n_evals: 75480` |

**The retracted claim never reached the site.** `main`'s most recent commit is "The 113x
speedup does not reproduce; record what does, and why". Nothing in `ZQ` publishes a
speedup figure: the only mention of Cython is an untyped tech tag on the home page. So the
correction did not need propagating, which is the good outcome.

No website change was needed for this repository, and the pin was deliberately left where
it is. Moving it for symmetry with the other projects would be churn against a citation
that is already true.

## What was not changed, and why

- **`requirements.txt` is unpinned**: `numpy`, `pandas`, `scipy`, `matplotlib`, `joblib`,
  `scikit-learn`, all without versions, in a repository whose subject is reproducibility.
  That is a real gap and it is **not** fixed here, for a reason: this review installed the
  current latest of all six, on Python 3.13, and the figures still regenerated
  byte-identically. Pinning is still right, but the pins have to be chosen against CI's
  Python 3.11 and verified there, which is its own change rather than a line edited in
  passing.
- **The four PNG figures have no dark variants.** They carry their own white plot
  background, so they stay legible on a dark page, and a dark set means teaching
  `generate_figures.py` a second matplotlib style while keeping the light PNGs
  byte-identical for the figure check. Worth doing; too large to fold in here.
- **The committed archives.** `Exercise3_Latex_Report_HBV.zip` and two under
  `Overleaf_Projects/` total about 24 MB of LaTeX sources, and the two big ones are LFS
  objects the workflow deliberately does not fetch, with the reason written in the
  checkout step. Left alone.
- **`code/`** is the assignment scripts as submitted, and the lint step covers `scripts/`
  only, with a comment saying why. Correct, and left.

## Guidance applied

- **[Security hardening for GitHub Actions](https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions)**:
  the `permissions` block, the job timeout, and the action bumps.
- **WCAG 2.1 AA, 1.4.3 Contrast (Minimum)**: the 4.5:1 floor for normal text, measured
  per class against every fill it is drawn on rather than assumed.
- **[Google Engineering Practices](https://google.github.io/eng-practices/)**: the
  `requirements.txt` pinning and the dark PNG figures were both declined explicitly as
  separate concerns, with the reasons recorded, rather than folded into a documentation
  change.

- **PEP 8 via ruff**, at the scope the project enforces, which passes.

  the orientation diagram it already owned.
